## Recommendation and design constraints

Extend the existing persistence into one authority-owned, transactional session checkpoint. Do not build a second terrain serializer or rely on independent subsystem shutdown saves. Single-player, listen-server and dedicated-server should use the same capture/load contract; clients receive authoritative reconstructed state through networking.

Read first: [source-of-truth design](voxel-earth-implementation-plan.md), [backlog](backlog.md), [M3 as-built record](m3-plan.md), [front end](front-end-plan.md), [land architecture](world-generation-architecture.md), [water architecture](water-architecture.md), [water persistence ADR](adr/0005-water-persistence.md), [water determinism boundary](water-determinism-boundary.md), [lattice ADR](adr/0010-two-lattice-jurisdictions.md), [crafting design](crafting-system-design-guide.md), [object geometry](object-geometry-snapshots.md), and [detached networking](detached-object-networking.md). Older roadmap/version prose is historical where the current code or newer design supersedes it.

Binding constraints: 2–16 co-op; server authority; offline single-player; time freezes offline; generated terrain remains canonical inputs plus edits; immutable diffusion tile data cannot be reproduced merely by rerunning a seed on another GPU. Keep codecs engine-free where possible. ADR-0005 permits irreducible CA state, but explicitly does not preapprove saving SWE grids or collapse schedulers. The newer water design makes scalar hydrology authoritative and GPU PBF particles reconstructible. Any new irreducible-state exception needs a focused design decision, not a silent extension of that ADR.

## Proposed checkpoint contract

Use `Saved/SaveGames/<world-uuid>/` with slot/display name independent of identity. Each committed generation has an immutable manifest, plus immutable payloads owned by that save (content-addressed blobs are optional initially). Keep a small `CURRENT` pointer and previous committed generations. Server storage roots are configurable. No dependence on a developer's absolute tile-cache path.

Manifest fields: container version; world UUID; checkpoint UUID/generation; optional parent generation; captured simulation tick and game epoch; UTC creation time only for UI; game/build compatibility; full-width seed; canonical terrain-provider/content identifiers; terrain/bake/amplifier and asset manifest/bank identities; material/item registry compatibility; terrain and craft log format, brick size and exact pitch in integer micrometres; independent water/hydrology/object/player section versions. Each section has name, required/optional status, encoded/raw lengths, compression and checksum/hash. Store uint64 values as integer binary fields or decimal JSON strings, not doubles.

Required sections for a feature-enabled session: terrain edits, craft edits/promotion state, objects and tombstones, players (online and offline), CA state, basin/river state, session clock and deterministic configuration. Explicit empty sections differ from missing sections. Record stream high-watermarks independently of compacted record count. Record simulation RNG state/timer remainders only where actual code uses non-derivable state; do not invent an NPC schema before NPCs exist.

Canonical tiles and asset banks must be pinned and available by verified content identity. First delivery can reference an immutable installed world pack plus required tile manifest; portable export copies required inputs. Refuse missing/mismatched inputs before generating anything. Never substitute synthetic terrain silently. A worldgen change generally needs compatible generator retention or a deliberate migration; changing the version number in an old log is not migration.

Codecs validate into temporary values with explicit endianness, bounded counts/lengths/decompression, finite transforms, valid IDs/pitches and exact section consumption. Preserve current core version distinctions. Unknown required sections/newer major versions refuse cleanly. Optional cosmetic sections may be dropped. Legacy imports are read-only inputs converted to a new checkpoint; report missing water/player/craft data and obtain an explicit recovery choice before claiming a faithful restore. Never overwrite the source during migration.

### One consistent capture

Introduce a world-owned session coordinator (`UE/VoxelSessionSubsystem.{h,cpp}`, proposed) with states Idle, Preparing, Loading, Playing, Capturing, Committing, Failed and Closing. A small game-instance travel descriptor may carry selected slot/seed across world replacement; avoid a process-global active slot as the authority.

At a defined game-thread boundary after completed authority physics/simulation steps, close mutation admission briefly, complete or defer authoritative edits/object promotions/transfers, synchronize authoritative asynchronous work, refresh registry dynamic state, and capture all sections under one checkpoint ID/tick. Pause the authoritative clock during the cut. Client cosmetic/GPU work is outside this barrier. If SWE contributes owned volume, use the existing approved flush-to-CA behavior under this cut and test uninterrupted equivalence; do not serialize an unapproved GPU grid.

Capture immutable handles/copies only; never let workers read actors, mutable registries or simulation objects. Hold page references until commit ends. Initially use bounded full snapshots; measure capture time and peak memory. If large edit logs exceed budget, add segmented immutable log snapshots or copy-on-write state with revision consistency rather than spreading mutable reads over frames. Resume gameplay after capture and encode/write asynchronously. One in-flight job; coalesce timer requests; explicit manual requests get clear busy/progress results. No successful-save timestamp before commit.

### Transaction and recovery

Write generation-unique temporary payloads on the same filesystem, finish/check/flush them, then the immutable manifest, and finally atomically replace `CURRENT`. Retain the previous valid manifest/pointer until the new one is durable. Implement a small storage abstraction and verify actual Windows replace/flush semantics; existing `SaveArrayToFile` plus rename demonstrates replacement intent, not proven power-loss durability. Unchanged terrain must still allow a new object/player/water generation without touching prior payloads.

Readers see one committed generation. A crash before pointer publication leaves the old one usable; abandoned staging files can be cleaned on next startup. After publication, validate all referenced payloads and fall back to a previous complete generation with a visible recovery notice. Disk full, permission failure, checksum failure, failed flush/rename or cancellation must never advance the slot or prune its last valid save. Garbage collection deletes only unreferenced blobs after successful commit/retention calculation, accounting for readers and pending jobs. Use a per-world writer lock to prevent two hosts writing one save concurrently.

Whole-checkpoint load failure stays at menu/server startup failure, preserving original files. An explicit recovery-as-new-world flow may omit damaged state, but normal Continue cannot quietly refill lakes or reset players. Save guards remain defense in depth. Deletion and overwrite use validated world/slot IDs and cannot escape the configured root.

### Load and reconstruction

1. Resolve and validate manifest, content availability and all required section payloads in staging. Keep current session untouched if switching validation fails.
2. Select/rebuild the UE world using saved seed/provider/configuration before amplifier, water and asset consumers initialize. Drain/cancel old jobs with session-generation tokens; stale callbacks cannot install into the replacement world.
3. Construct canonical terrain/assets; replay terrain then craft into fresh core state; rebuild edit-derived admission, coarse projection and collision inputs.
4. Restore clock before tide/gameplay water evaluation. Rebuild basin/river topology from pinned inputs, apply ledger/graph, then CA fills, active set and mobilized keys using existing core contract. Ensure pending graph state remains durable when a solver is disabled.
5. Install object registry, stable IDs, revisions, tombstones and ownership references; restore needed actors with saved velocities/lifetimes. Keep distant objects dormant. Resolve player/object references in a second pass. Suppress prototype/default spawning during restore.
6. Restore player records before defaults/possession; check safe spawn and wait for collision readiness. Persist absolute world coordinates plus units, not camera-relative values.
7. Release simulation/joins only after authoritative state is ready. Client rendering readiness is a separate gate. Rebuild meshes, GPU pools, light, particles and ripples within existing budgets.

Suggested initial autosave policy: every five minutes of active authoritative simulation, coalesced while busy, retaining five completed autosave generations per world; named manual saves never implicitly pruned. This is a proposal, not existing timer behavior. Save-and-quit awaits completion and reports failure with retry/quit-without-saving choices. Server shutdown stops new joins/intents, captures before actor teardown, drains the writer, then exits. A remote client leaving does not shut down or save the shared server world; logout records its latest authoritative state in memory for the next checkpoint. Offline time advances neither simulation nor item/debris timers.

## Multiplayer identity and synchronization details

Persist players under world UUID plus stable authenticated account ID (platform/provider namespace included). Offline single-player uses a local profile UUID. For LAN without account services, provision a server-issued reconnect credential with a documented trust boundary; never key ownership by display name, IP address, controller object name or connection index. Persist mappings server-side; reject simultaneous possession of the same identity. Host identity is one player record, not slot metadata. No automatic host migration in the initial scope; a transferred complete save requires deliberate account remapping where providers differ.

Server validates item use/pickup/crafting and owns inventory before persistence is advertised for MP. Serialize item names as stable registry strings, not process-local FName indices. Unknown items trigger migration/refusal, not silent deletion. Logout captures before controller destruction; reconnect consumes the existing record and must not duplicate pickup/throw transactions. Ownership on `FEntry::OwnerId` needs an explicit mapping to persistent players.

Bootstrap takes an authoritative cut with per-stream watermarks. Existing terrain live-batch buffering is retained but extended to session identity and completion acknowledgment; detached transfer epochs remain connection-local and reset on reconnect. Send required terrain/craft/hydrology/player state and relevant objects, then apply buffered newer changes exactly once. Gate player intents until bootstrap completes. Bound buffers and restart bootstrap on overflow. Disk-compacted logs do not reset live sequence numbers. Restart rotates the network session epoch so packets from the old server cannot mutate the new session. Persist authoritative clock and immediately announce restored epoch/time scale before water gameplay starts.

## Validation and risks

Reuse `voxel-core/tests/test_editlog.cpp`, `test_craftpersist.cpp`, `test_waterca.cpp` and existing water/hydrology tests; verify exact filenames when adding coverage. Reuse UE object persistence/registry/pages/network assembly tests, `VoxelSaveJobsProbe.cpp`, `tools/verify-async-saves.py`, `tools/verify-detached-persistence.py`, `tools/verify-object-persistence.ps1` and `tools/verify-detached-network.ps1`. Their existence does not establish they pass on this checkout; none were executed for this planning task.

Required tests:

- Round-trip terrain and craft digests, negative/large coordinates, promoted cells and compaction replay; verify stream watermarks remain valid.
- CA volume/digest and active/mobilized ownership; basin ledger and pending/active graph round-trips; save mid-flow and compare deterministic continuation. GPU cosmetic particle patterns need not match.
- Detached object-only updates, dormant geometry page hydration, stable GUID/revisions, deleted tombstones, velocity and remaining lifetime; actor failure rolls back staging. Physics continuation requires semantic/tolerance checks, not promised bit-exact Chaos trajectories.
- Restart clock/tide at saved time after a long real delay; no offline expiry/catch-up. Cross-seed and same-seed slots cannot leak state.
- Inventory restore without default reseeding, player-ID collisions, disconnect during pickup, late join during save, packet loss/reorder, reconnect and server restart; clients cannot author persisted state.
- Truncation, invalid versions/pitch/provider/assets, missing required payloads, oversized counts/decompression, disk full, interrupted commit, writer lock collision, interrupted migration, pruning while a snapshot holds page references and restart after quarantine.
- Measure capture pause, worker duration, memory peak, save size and load-to-authority/client-ready separately; use project benchmark policy for implementation changes (>5% regressions require resolution). Set explicit capture budgets from P0 measurement; do not promise a millisecond target without hardware evidence.

Largest risks are incomplete state classification, initialization-order changes in the very large world subsystem, independently evolving craft pitches/assets, unsafe partial hydrology restore, missing MP inventory authority, and snapshot copy costs. Address completeness and atomic commit before UI polish. Do not describe the result as complete multiplayer saving until P4's multi-process restart/rejoin gate passes.
