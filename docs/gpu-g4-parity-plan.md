# G4 — pooled-path parity with the component renderer

Written 2026-07-25 after G3 landed, from reading the CPU path rather than from
the G0 checklist. Two of the three items turn out to be much cheaper than
recorded, and all three funnel through one gate that was not previously called
out.

## The gate: every remaining item needs a material graph change

`M_VoxelTerrain` reads its per-chunk inputs as **named material parameters** set
on a per-chunk `UMaterialInstanceDynamic`. Pooling deletes the per-chunk MID by
construction -- one primitive, one material, thousands of chunks -- so no
remaining parity item can be delivered by C++ alone. Each needs its value to
arrive as a **vertex interpolant** the graph reads instead.

The material is generated by `ue-project/Tools/create_voxel_material.py` and is
regenerable headlessly:

```
UnrealEditor-Cmd.exe <uproject> -run=pythonscript -script=Tools/create_voxel_material.py \
  -unattended -nop4 -nosplash
```

**This is the risk to manage.** `M_VoxelTerrain.uasset` is a binary asset the
SHIPPING CPU renderer depends on. Any change must leave the component path
byte-identical, which means the new interpolant path is gated behind a switch
that defaults to current behaviour, not swapped in. Verify by rendering the CPU
path before and after and diffing the screenshots, not by reasoning about the
graph.

The pooled vertex factory already declares `TexCoords : TEXCOORD0`, currently
carrying only derived UVs, so there is an interpolant channel available without
widening the vertex layout.

## 1. Ring cross-fade — cheaper than recorded

The G0 checklist listed this as needing "a per-chunk buffer". It does not.
`ApplyRingFadeParams` calls `ComputeRingFadeParams(ChunkLevel)` -- the four
scalars are a **pure function of ring level**, nothing per-chunk about them.

And the pooled chunk table already encodes level: entry `.w` is the mip scale,
`float(1 << Level)`, so `log2(w)` recovers the level exactly (it is always an
exact power of two, so the float result is exact).

So: no new buffer, no extra memory. The vertex factory computes

```
CameraDistance = distance(WorldPosition, CameraPositionWS)
InnerRamp = saturate((CameraDistance - InnerStart) / (InnerEnd - InnerStart))
OuterRamp = saturate((OuterEnd - CameraDistance) / (OuterEnd - OuterStart))
FadeFactor = InnerRamp * OuterRamp
```

with the per-level constants supplied as a small fixed array in the factory's
uniform buffer (6 levels x 4 floats), and passes `FadeFactor` out on the spare
interpolant channel. The material feeds it to the same `DitherTemporalAA` ->
OpacityMask it uses today.

Do this one first: it is the only remaining item that affects how the game looks
in normal play, and it is the smallest.

## 2. Per-chunk debug tints — genuinely per-chunk, but debug-only

`SetDebugTint`/`ClearDebugTint` write a `DebugTint` vector on the per-chunk MID,
driving the P1 chunk-state tints (just-loaded / edited / re-meshed) and the ring
tints under `voxel.Debug 2`.

This one does need per-chunk storage. Natural home is the existing chunk table:
`ChunkClimate` is a `StructuredBuffer<float2>`, and widening it to `float4`
(xy = climate, zw = free) costs 8 bytes per chunk -- against a table sized in
thousands of entries, not millions, so it is noise. Tint is a colour, so pack it
as RGBA8 into one of the free floats' bits rather than widening again.

Lower priority than (1): it is a debug affordance, invisible in normal play, and
its absence does not block G5.

## 3. Voxel GI light field — the real work

The CPU path bakes GI into vertex colour G at mesh time (`AO x GI`), on the
worker thread, per quad. The pooled path has no per-quad channel free: R is the
sky-facing flag, G is AO, B/A are climate.

Options, in increasing order of cost and fidelity:

- **Leave GI in G, drop AO.** Free, immediate, and wrong-looking in caves,
  which is where GI matters.
- **Widen the packed quad from 8 to 12 bytes** to carry a GI byte. Touches the
  CPU/GPU packing contract (`PackVoxelChunkQuad` <-> `VoxelQuadDecode.ush`) and
  the GPU mesher's emit, and costs 50% more pool memory. Keeps the CPU/GPU
  digest gate meaningful only if both sides change together.
- **Make the light field a GPU-readable volume texture** and sample it in the
  material by world position. This is the option ADR-0006 assumed. No per-quad
  cost, correct under edits, and it decouples lighting updates from re-meshing
  entirely -- a dig currently re-meshes a chunk partly to refresh baked GI.

The third is the right end state and the largest piece of remaining GPU work.
It is also independent of (1) and (2), so it should not gate them.

## 4. Water surface

A separate, near-identical instance of the terrain pool: its own quads, its own
material, same one-primitive-one-draw shape. Deliberately out of scope until
terrain parity is closed -- doing it first would mean maintaining two immature
pools.

## Suggested order

1. Ring cross-fade (visual, small, unblocks G5)
2. GI volume (large, independent, the real prize for cave lighting)
3. Debug tints (debug-only)
4. Water pool (separate system)

G5 -- flipping `voxel.Stream.GPU` on by default and retiring the per-chunk
component machinery -- wants (1) at minimum. (3) can trail it.
