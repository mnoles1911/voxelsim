# Production environment render ownership

Status: provenance, a publication transaction, a fail-closed UE adapter and tests are implemented. Ordinary generated trees still use the existing terrain renderer. No replacement actors are spawned and no terrain materials are hidden by this change.

## Implemented prerequisite

`voxelcore/assetownership.h` identifies an instance from world seed, provider/catalog fingerprints, canonical signed anchor, bank seed, layer and quarter yaw. The ID is stable across chunk boundaries, cache eviction and actor recreation. Full provenance remains beside the 128-bit hash so a collision or changed source cannot silently attach an old ownership record to a different asset. Provider/catalog changes require an explicit persistence migration; numeric bank IDs alone are not a cross-catalog identity.

`AssetField::ResolvedAssetInstance` now preserves bank, seed and species indices. Composition behavior is unchanged. The additional indices occupy the existing padding on the current 64-bit layout, rather than adding grid copies.

`AssetRenderOwnership` has separate visible and prepared snapshots. Promotion requires matching object/projection revisions, hidden object readiness and every required CPU/GPU page. Failed publication or cancellation leaves the visible owner unchanged. Successful publication advances the generation, rejecting old visible jobs. Demotion likewise requires a current coarse projection. `assetTerrainRenderInstances` preserves first-non-air ordering among survivors and is exclusively a rendering filter; it must never filter authoritative world/collision queries.

`VoxelProductionEnvironment::FAdapter` is the game-thread bridge. It captures immutable snapshots for workers and refuses claims unless the renderer supplies an atomic publication callback. Its first-pilot admission also requires evidence of a canonical 100 mm source, composition-correct visible cells, a complete touched-page set and an unedited terrain footprint. Those checks are intentionally restrictive: ordinary edited trees and 50 mm sources need additional integration.

Core tests cover both-backend readiness, failed publication, cancellation, stale generations, demotion projection revisions, source identity, stable render ordering and resolved bank provenance. `Voxel.Objects.ProductionOwnership` checks the UE adapter's fail-closed behavior and immutable snapshots. The focused CMake target is `vxc_assetownership_tests`. These tests verify the prerequisite transaction, not a functioning production renderer switch.

Verification: the focused Release target built successfully and all four core tests passed; output is in `Saved/asset-ownership-core-tests.log`. UE adapter automation is separate from that result.

## Exact bridge still required

1. Enumerate canonical candidates from `VoxelResolveTerrainInstances` / `ResolvedAssetsForFootprint` in `VoxelWorldSubsystem.cpp` (around lines 17951 and 18533). Preserve the production bank/provider fingerprint and classify trees from the manifest. Do not identify candidates by material or by the four prototype asset names.
2. Build an arbitrary-spec object from the canonical bank grid using `InitializeAssetFromVxa` and the generic source descriptor. Arbitrary identities now survive snapshots and staged restoration; the legacy four-name mapping is retained only for compatibility. Clip object-visible cells against the same canonical first-non-air composition: simply drawing an entire bank tree can expose cells that terrain or another asset originally won. Start with unchanged 100 mm trees; finer banks are a separate authoring/integration step.
3. Capture one immutable ownership generation at request dispatch. Apply the same render filter in the CPU cached/uncached worker paths (around 25417 and 25729), GPU asset request assembly (around 23870), and overlay-aware render path. Keep `GeneratedWorld`, world collision, admission bounds and edit logs authoritative and unfiltered. An edited brick already contains generated asset material, so skipping only its original bank stamp is not enough; the initial adapter therefore refuses edited footprints.
4. Stage replacement terrain payloads without making their index entries visible. The current GPU brick path publishes before `OnGpuMeshJobComplete` reaches `DrainResults`; the `GenerationId` check around 28565 is therefore too late for ownership publication. CPU paths separately apply quads and then publish brick packs around 28618/28636 and 28877/28885. Both require a holding area for transaction payloads, including all-air pages.
5. Add a renderer transaction that replaces every affected terrain index/page and reveals the prepared object together, after upload readiness. Existing `PublishDeferredGpuIndexAdds` only orders a claim before the next index upload; it is not a multi-page/object transaction. Preserve old slots until the new batch is committed. Include parked/speculative chunks, adoption, cross-chunk aprons and all currently visible coarse levels; otherwise an old tree can return when a chunk is adopted or LOD changes.
6. Carry the ownership generation through GPU requests, worker results, parked caches and cancellation. Invalidate pending old generations before they can publish, not only after they reach the game-thread drain. Account for actor destruction or a world/catalog reload during preparation.
7. Add provenance-preserving local edits and a saved coarse projection before admitting modified trees. Distance demotion must use the latest edited projection, never regenerate the original tree. Integrate registry stable IDs and source provenance into the versioned persistence schema. Rendering wind remains presentation-only; collision and cut coordinates stay in the authoritative local grid.

This is a renderer publication refactor, not a safe two-site filtering patch. Enabling actor overlays before steps 2–6 would create duplicate geometry, holes or stale tree resurrection. Acceptance must include an isolated cross-chunk tree moving near/far, CPU and GPU production, cancellation during upload, parked-chunk adoption, an edit followed by demotion/reload, and multiplayer ownership synchronization.
