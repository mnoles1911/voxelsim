# Production environment render ownership

Status: provenance, a publication transaction, a fail-closed UE adapter and tests are implemented. Ordinary generated trees still use the existing terrain renderer. No replacement actors are spawned and no terrain materials are hidden by this change.

## Implemented prerequisite

`voxelcore/assetownership.h` identifies an instance from world seed, provider/catalog fingerprints, canonical signed anchor, bank seed, layer and quarter yaw. The ID is stable across chunk boundaries, cache eviction and actor recreation. Full provenance remains beside the 128-bit hash so a collision or changed source cannot silently attach an old ownership record to a different asset. Provider/catalog changes require an explicit persistence migration; numeric bank IDs alone are not a cross-catalog identity.

`AssetField::ResolvedAssetInstance` now preserves bank, seed and species indices. Composition behavior is unchanged. The additional indices occupy the existing padding on the current 64-bit layout, rather than adding grid copies.

`AssetRenderOwnership` has separate visible and prepared snapshots. Promotion requires matching object/projection revisions, hidden object readiness and every required CPU/GPU page. Failed publication or cancellation leaves the visible owner unchanged. Successful publication advances the generation, rejecting old visible jobs. Demotion likewise requires a current coarse projection. Do not use `assetTerrainRenderInstances` to compose replacement terrain: removing an owned winner would expose a later overlapping asset. Resolve the winner from the complete original ordered list, then suppress its rendered cell if owned, as demonstrated by `assetTerrainRenderMaterial` in `assetcandidate.h`. Authoritative world/collision queries remain unfiltered.

`VoxelProductionEnvironment::FAdapter` is the game-thread bridge. It captures immutable snapshots for workers and refuses claims unless the renderer supplies an atomic publication callback. Its first-pilot admission also requires evidence of a canonical 100 mm source, composition-correct visible cells, a complete touched-page set and an unedited terrain footprint. Those checks are intentionally restrictive: ordinary edited trees and 50 mm sources need additional integration.

Core tests cover both-backend readiness, failed publication, cancellation, stale generations, demotion projection revisions, source identity, stable render ordering and resolved bank provenance. `Voxel.Objects.ProductionOwnership` checks the UE adapter's fail-closed behavior and immutable snapshots. The focused CMake target is `vxc_assetownership_tests`. These tests verify the prerequisite transaction, not a functioning production renderer switch.

Verification: the focused Release target built successfully and all four core tests passed; output is in `Saved/asset-ownership-core-tests.log`. UE adapter automation is separate from that result.

4. Stage replacement terrain payloads without making their index entries visible. The current GPU brick path publishes before `OnGpuMeshJobComplete` reaches `DrainResults`; the `GenerationId` check around 28565 is therefore too late for ownership publication. CPU paths separately apply quads and then publish brick packs around 28618/28636 and 28877/28885. Both require a holding area for transaction payloads, including all-air pages.
5. Add a renderer transaction that replaces every affected terrain index/page and reveals the prepared object together, after upload readiness. 6. Carry the ownership generation through GPU requests, worker results, parked caches and cancellation. Invalidate pending old generations before they can publish, not only after they reach the game-thread drain. Account for actor destruction or a world/catalog reload during preparation.

This is a renderer publication refactor, not a safe two-site filtering patch. Enabling actor overlays before steps 2–6 would create duplicate geometry, holes or stale tree resurrection. Acceptance must include an isolated cross-chunk tree moving near/far, CPU and GPU production, cancellation during upload, parked-chunk adoption, an edit followed by demotion/reload, and multiplayer ownership synchronization.

## Approved appearance binding at composition handoff

The appearance packet is bound to the original source VXA digest and samples in original source coordinates. `assetBuildCandidateVxa` currently emits composition-clipped geometry with quarter yaw baked into its indices. That output has a different digest and coordinate frame. Passing it directly to `InitializeAssetFromVxa` cannot preserve approved appearance: supplying the original digest fails integrity validation, while supplying the clipped digest has no matching appearance packet.

The production handoff must retain original source identity separately from clipped geometry identity and preserve an exact inverse mapping to source cells and face directions. Validate the clipped geometry against the original source and canonical composition before accepting that binding. Save and restore must retain the same mapping; do not weaken the existing source digest check or write a fabricated sidecar for the clipped digest. This requirement applies to appearance variation, cutout coordinates, detached geometry and newly exposed faces after edits. Acceptance needs a non-square source with negative origin under every quarter yaw, an overlapping winner, a terrain-clipped portion, and edit/save/restore checks against the original appearance samples.

`assetCandidateSourceSample` now supplies the bounded inverse cell and face-direction mapping in the core helper. It returns original origin-inclusive cell coordinates and original face axis/sign. `assetCandidateSourceVertex` maps unit-box corners as well: because canonical yaw rotates voxel indices, reflected box corners need a one-cell correction to preserve the original leaf UV phase. Neither helper authorizes an appearance binding or establishes composition visibility. The game appearance view and composed importer now implement and validate this source mapping, while automatic world selection and ownership publication remain unwired.


## Verified composed import and current GPU work (2026-09-08)

`InitializeComposedAssetFromVxa` keeps the original appearance identity separate from the clipped geometry digest. It checks both digests, 100 mm pitch, canonical rotated bounds, source-material membership of every retained cell, and the original appearance packet. Generic descriptor schema 2 retains the clipped digest and source quarter yaw across synchronous and staged restoration. The ordinary importer still refuses composed descriptors. The importer does not itself prove which cells canonical world composition should retain.

Native `Voxel.Environment.ComposedActor` passed all four quarter yaws, source colors and leaf UV coordinates, clipping, carving, synchronous/staged restoration, and invalid-input refusals. The final report is `asset-forge/out/tree-runtime-appearance-v1/composed-import-tests2/index.json`. Four appearance regressions also passed in `composed-import-tests/Voxel.Appearance/index.json`, including real-tree felling. The initial composed test report is retained: its failures were an incorrect test expectation of opaque alpha, corrected to the existing bark material-class value without changing rendering.

The opt-in GPU stamping implementation is now compiled and GPU-validated on D3D12 SM6 / RX 7800 XT. `FAssetInstance.RenderOwned` retains the complete ordered source list: classic stamping clears owned winners after all stamps, and worklist stamping clears them after the ordered column loop. `Voxel.GPU.AssetOwnedWinner` passed comparisons of both GPU paths with an independent CPU reference over 64 cases, including default ownership-off cells and preserved upper bits. `Voxel.Objects.ProductionEmptyStage`, `ProductionOwnership`, and `ProductionPageBatch` also passed: four tests, zero warnings or failures in `asset-forge/out/tree-runtime-appearance-v1/gpu-ownership-tests/index.json`. Empty pages retain complete descriptor payloads; null payloads remain failures. The new large-region wrapped clear dispatch still needs execution coverage. No WorldSubsystem path sets ownership yet, and these tests do not prove world-level publication.

Engine-source inspection shows that `BeginRenderingViewFamilies` sends all end-of-frame component updates and synchronizes render command pipes before queuing views. This may support a single game-thread page/object commit, but it is not frame-level evidence of atomic publication. Scene captures, page index ordering, hidden object readiness, cancellation, and producer generation invalidation still require implementation and validation. The default GPU allocator also lacks the whole-batch reservation used by the CPU-allocated prepared-page pilot; do not silently switch allocation modes or claim that pilot completes the production path.
