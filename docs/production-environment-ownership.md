# Production environment render ownership

Status: provenance, an ownership transaction, a fail-closed UE adapter, render-only winner suppression support, and an opt-in hidden candidate preparation bridge are implemented. Ordinary generated environment assets still use the existing terrain renderer. The runtime preparation command can spawn a hidden, collision-disabled candidate; it does not publish that actor or suppress production terrain. Atomic production handoff is not implemented.

## Implemented prerequisites

`voxelcore/assetownership.h` identifies an instance from world seed, provider/catalog fingerprints, canonical signed anchor, bank seed, layer and quarter yaw. The ID is stable across chunk boundaries, cache eviction and actor recreation. Full provenance remains beside the 128-bit hash so a collision or changed source cannot silently attach an old ownership record to a different asset. Provider/catalog changes require an explicit persistence migration; numeric bank IDs alone are not a cross-catalog identity.

`AssetField::ResolvedAssetInstance` preserves bank, seed and species indices and has an explicit render suppression marker, defaulting to false. The marker grows the current 64-bit record from 40 to 48 bytes. Authoritative composition remains unchanged. CPU render sampling and classic/worklist GPU stamp support preserve the original first non-air winner before applying suppression; production World request assembly now captures an immutable render context, marks private request copies, and carries ownership generations through results and parked geometry. The adapter remains callback-less, so actual production ownership cannot change. See [render suppression support](environment-render-suppression.md) for buffer bounds and backend tests.

`AssetRenderOwnership` has separate visible and prepared snapshots. Promotion requires matching object/projection revisions, hidden object readiness and every required CPU/GPU page. Failed publication or cancellation leaves the visible owner unchanged. Successful publication advances the generation, rejecting old visible jobs. Demotion likewise requires a current coarse projection. The CPU reference `assetTerrainRenderMaterial` resolves the original first non-air winner, then suppresses that cell if the winner is object-owned. Removing owned instances before composition is incorrect: it reveals later overlapping geometry. The former unused instance-filter helper was removed. Authoritative world/collision queries remain unfiltered.

`VoxelProductionEnvironment::FAdapter` is the game-thread bridge. It captures immutable snapshots for workers and refuses claims unless the renderer supplies an atomic publication callback. Its first-pilot admission also requires evidence of a canonical 100 mm source, composition-correct visible cells, a complete touched-page set and an unedited terrain footprint. Those checks are intentionally restrictive: ordinary edited trees and 50 mm sources need additional integration.

Core tests cover both-backend readiness, failed publication, cancellation, stale generations, demotion projection revisions, source identity, stable render ordering and resolved bank provenance. `Voxel.Objects.ProductionOwnership` checks the UE adapter's fail-closed behavior and immutable snapshots. The focused CMake target is `vxc_assetownership_tests`. These tests verify the prerequisite transaction, not a functioning production renderer switch.

## Hidden preparation implemented

`VoxelProductionCandidatePreparation` and `VoxelWorldSubsystem.cpp` now provide runtime-only `voxel.Environment.PrepareCandidate` and cancellation commands. Selection uses real resolved bank/manifest inputs and provider/catalog fingerprints, without a fixture-name restriction. Admission requires a canonical 100 mm environment source, resident terrain, bounded work, and an unedited footprint. The worker re-resolves the full candidate footprint, including earlier winners, and clips an immutable VXA against canonical terrain/asset composition.

Preparation retains canonical yaw and the full source content hash separately from clipped geometry identity. The actor uses anchor translation only because rotation is already baked into the clipped cells. All geometric footprint/apron page keys across supported LODs are enumerated; bounded game-thread scans revalidate edits and track visible, pending, and parked coverage. Worker lifetime is tracked through `InFlightTasks`; cancellation and edit/residency epochs reject stale results. These checks establish preparation readiness, not publication readiness: the live streaming page set can still change.

The arbitrary-spec actor is staged incrementally, hidden, with collision disabled. An explicit unpublished-preparation predicate excludes it from modern registry discovery and legacy detached capture, including teardown. Generic hidden live objects remain eligible for persistence. `PublishStagedObjectRestore` is not called by preparation. Tests cover candidate admission, immutable clipping inputs, stale/cancelled results, and persistence exclusion; build/runtime evidence should be read from the current handover rather than inferred from this design document. See [candidate preparation](production-candidate-preparation.md).

## Remaining atomic production handoff

The initial pilot must explicitly require unchanged canonical 100 mm sources, unedited terrain, and brick marcher rendering. Select CPU pool allocation before pool initialization; real GPU generation is still allowed through held requests. Preserve the default GPU allocator refusal in `PublishPreparedBatch`. Supporting its GPU arena allocator needs a separate verified reservation implementation.

1. **Capture the complete affected page transaction.** Start from the prepared footprint and apron keys at every LOD. Snapshot visible, pending, parked, and absent keys, including chunk generation, pool allocation token, edit/residency epochs, and ring placement. Absent keys require a future-generation barrier; do not publish every geometric key into toroidal render indices. Include footprint-band speculative caches. Cancel conservatively if the captured page coverage or ring placement changes during preparation.
2. **Propagate immutable ownership generations throughout World.** Extend `FJobResult`, `FChunkRecord`, `FGpuPendingJob`, and `FParkedGeometry`, capturing one snapshot at dispatch. Integrate `DispatchJobs`, `SubmitGpuMeshJob`, `OnGpuMeshJobComplete` before its speculative branch, `DrainResults`, mesh/pool application, `ParkChunk`, `ParkSpeculativeResult`, parked adoption/eviction, footprint-band bookkeeping, and remesh invalidation. A late chunk `GenerationId` check cannot protect GPU resident claims that already published.
3. **Quiesce affected work before staging.** A per-key barrier blocks demand dispatch, speculation, and parked adoption while previously submitted affected jobs drain. Capture final pool tokens afterward; a bounded timeout cancels preparation. The GPU manager currently offers `CancelAll`, not per-job cancellation, so do not cancel unrelated work globally. Replacement GPU requests use `Submit(..., bHoldBrickPublication=true, OwnershipGeneration=...)` and route their held results directly to the adapter before ordinary completion handling. Old jobs must be invalidated before any early visible publication.
4. **Generate canonical replacements on each required backend.** Keep the complete ordered instance list and mark the owned winner; never remove an owned instance before sampling. Integrate CPU cached, uncached, and coarse render samplers and GPU request assembly. Preserve authoritative `GeneratedWorld`, collision, admission bounds, and edit logs. Any cache storing composed materials needs an ownership-generation key or separation; column-only caches can remain shared. With the adapter's default CPU/GPU readiness requirement, actually generate and validate both per page, then select one payload for publication. Do not mark a backend ready merely because the other completed. Bound total pages, staged bytes, worker concurrency, and lifetime, including valid all-air payloads.
5. **Complete pool reservation and stale-slot admission.** `FVoxelBrickPreparedReplacement` carries `ExpectedSlot` and `ExpectedSequence`. The public game-thread `SnapshotAllocation` accessor now returns explicit presence, slot and allocation sequence, with canonical absent values; it is an observation, not a reservation. `Voxel.Objects.BrickAllocationToken` exercises stale absence, remove/reinsert rejection, and current-token admission. `PublishPreparedBatch` already validates and reserves all CPU-arena ranges before retiring old pages, rolling back allocations on failure. Introduce a reservation handle if registry or renderer admission can still fail after allocation. Hold old visible pages until the transaction can commit without another fallible step.
6. **Prove one rendered-frame publication boundary.** Current pool `Flush` queues an upload graph and invokes `IndexSink` separately. Calling `PublishPreparedBatch` followed by actor publication on the game thread does not by itself prove atomic rendering. Prepare actor render resources while hidden, then coordinate terrain index replacement and object visibility at one renderer-controlled frame boundary after upload readiness. Cover color, depth, and shadow passes. Do not advance visible ownership or reveal the object until this boundary is guaranteed.
7. **Reserve and bind the provenance stable ID explicitly.** Check registry admission using `AssetProvenance::StableId` and prepared immutable geometry while the actor remains excluded from discovery. Clearing its preparation flag first would allow `RefreshObjects` to bind an ordinary/random ID. Roll back reserved registry admission if pool publication fails. At successful commit, bind the exact ID before discovery or replication can expose the actor, and prevent replication before the page transaction commits. Optional schema-2 descriptor provenance now retains the full source fields and canonical hash; migration policy and registry/ownership restoration still need integration. The initial rendering pilot must not claim save/reload completeness.
8. **Retain ownership after publication.** Stop applying the hidden-preparation destruction timeout once an actor owns terrain render cells. Future streaming generation and parked adoption must use the published ownership snapshot. Actor destruction, editing, world/catalog reload, and distance demotion require a reverse atomic transaction or explicit pilot restrictions until supported. Local edits need provenance-preserving state and a saved current coarse projection; demotion must never regenerate the original unedited asset. Rendering wind remains presentation-only, with collision and cut coordinates in the authoritative local grid.

## Acceptance still required

Before enabling the pilot, exercise CPU and real GPU generation with a canonical cross-chunk asset, overlapping earlier/later instances, aprons, all affected visible LODs, pending jobs, and parked adoption. Prove identical first-winner suppression, preserved unfiltered world/collision queries, and bounded staged memory. Test allocation refusal/exhaustion, all-air replacements, cancellation during upload, stale edit/residency/ring generations, actor destruction, and registry ID conflicts. Each pre-commit failure must preserve old terrain and keep the actor undiscoverable, invisible, and collision-disabled.

Capture rendered frames across the actual commit to prove there are neither duplicate assets nor holes in color, depth, or shadows. Verify provenance stable-ID binding and absence of premature replication. Subsequent production acceptance also requires movement near/far, edit then demotion/reload, provenance migration, and multiplayer ownership synchronization. Hidden preparation and backend unit/parity tests do not establish these results.

This remains a renderer publication refactor, not a two-site filtering change. Keep ordinary production output unchanged until the complete transaction and its acceptance tests are implemented.

## Registry reservation and page lifetime prerequisites

Current validated additions: `PrepareHeldCpuPages` now prepares keyed private CPU packs across the allocated affected pages, under complete-page freeze and eviction-pressure pins, then validates and discards them. The attached march index now supplies prepared-batch storage/credit admission before pool mutation. Build19actions85.61s,35DX12tests and a real18pack/27page run passed with normal exits. See `environment-held-page-preparation-plan.md` and `prepared-index-delivery.md`. GPU-held request construction/parity is the active next step. No production ownership publication or backend readiness is claimed.

The next integration adds `FRegistry::ReserveProduction`, `CommitProduction`, and `RollbackProduction`. Reservations are separate from ordinary registry entries and therefore invisible to snapshots, discovery, streaming and replication. They retain the provenance-derived ID and fully validated bounded geometry/dynamic payload. Stale and foreign tokens cannot release a newer reservation. Existing IDs and tombstones are never replaced. Commit requires a capturable published actor with the exact prepared state, or a validated originally actorless dormant entry; failed commit retains the reservation. This API does not reveal an actor or publish terrain and has no World call yet.

`VoxelEnvironmentPages::FBarrier` supplies a bounded game-thread ledger independent of `ChunkRecords`. Actual World CPU/GPU dispatch now acquires leases that survive worker completion, result enqueue and chunk unload until final consumption/discard. Speculative completion and teardown also retire leases. The default rendering path has no active page freeze. The explicit `voxel.Environment.RehearseHandoff` diagnostic prepares a hidden candidate, freezes its complete page set, drains existing work, snapshots pool allocation observations and checks them on the following tick. It releases without publishing, refuses changed anchors/rings/tokens and has a 30-second freeze timeout. It does not pin allocations; pressure changes fail closed. The rehearsal's new runtime verification is pending.

The combined Unreal build passed in `build-environment-persistence-reservations-fixed.log` (5 actions,51.78s); all30 object tests passed with normal exit0 in `environment-persistence-reservations-tests.log`, including the new reservation and three page-barrier tests. A test-only ambiguous `FKey` name caused the first build failure and was qualified before this successful rebuild.

The later World rehearsal and ordered-index checkpoint passed17buildactions54.54s and all33DX12objecttests. Real `environment-ordered-rehearsal-probe.log` passed and exited0:27pages frozen,38ticks waiting for affected producers,20visibleResident/2pending/0parked/5absent observed stable across a tick, then the freeze released. This establishes observation-only quiescence under actual streaming; allocator pressure is not pinned and no actor/page publication occurs.
