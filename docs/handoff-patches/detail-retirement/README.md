# Unapplied detail mesh retirement pilot

`retirement.patch` is against the live source hash in `source.sha256`. It has NOT been applied, compiled, or run. Applying it changes the detail bake builder identity and requires the coordinated cache rebuild/validation workflow. Do not bypass that identity check.

Flag: `-VoxelDetailRetireUnused`. This is opportunistic retirement, not a hard memory cap.

The barrier follows cache/result drain, installations, unload and HISM rebuild. It requires empty InFlight, Results, PendingGeometry, CacheLoads, PendingCachedMeshes, CacheChecks and fallback count, no unresolved failure, and every registered task completed. Only unused, clean, zero-instance components whose mesh is not compiling qualify. Newly applied groups/installations reset the 30-second grace. At most 32 keys are inspected and two retired in a tick; new resolve dispatch is suppressed on a retirement tick. Snapshot/alias scans have explicit size ceilings (4096 map keys, 8192 mesh roots). HISM destruction/detachment plus both UPROPERTY root arrays are handled. Cached resource aliases and every duplicate mesh root are removed only after the last mesh-key alias disappears. Source banks/catalogs/failure policy remain untouched. GeometryKnown clears only behind the full barrier, allowing exact revisit restoration.

Counters report probes, retired keys, objects unrooted, barrier-deferred ticks, size-limit skips, time continuously blocked, mesh/cache/root/component counts, and pending scan keys. `blockedSeconds` measures the global barrier, not proof that an eligible unused object exists. No resource-byte reclamation is asserted: engine references and normal later GC may retain objects.

## Required validation before application acceptance

- Build after coordinated source/cache identity update; no live patch against active captures.
- Retirement OFF must preserve route placement counts/digests and rendering.
- ON: leave a region for >30 seconds, verify keys/roots/components decrease, then revisit and compare transforms/species/seed counts against OFF; verify missing GeometryKnown promises regenerate or reload resources.
- Hold a geometry worker, result, cache file check, async load, ready mesh, or fallback task individually: no retirement before drain. Include completed worker with queued result and a cache result ready before package/mesh compilation.
- Two keys alias one cached mesh: first retirement keeps resource and mesh root; last removes all cached aliases/root duplicates. A nonempty group or dirty HISM always prevents removal.
- Shutdown while worker or async load outstanding remains safe. No explicit GC/flush is introduced; measure ordinary subsequent GC cost separately.
- Continuous travel: report deferred/starved behavior honestly. The pilot may never retire while continuously busy.

## Bounded brief drain as the next phase

A bounded pause can improve opportunities without indefinite visible starvation: when an aged unused key exists, stop only NEW detail resolve dispatch for at most 250 ms, while continuing result/cache drains, mesh installation, unloading and HISM rebuild. Retire only if the same exact barrier becomes true; otherwise abort the attempt, resume dispatch, and cool down for 5 seconds. Never clear promises or cancel active loads to force the barrier. Keep existing groups/meshes visible throughout. Instrument pause duration, aborts, oldest pending promise and time-to-visible for new groups. This still is not a hard residency cap; a strict cap requires admission/backpressure or independently owned per-resource promises, a larger architectural change. No bounded-pause code is included in this patch.
