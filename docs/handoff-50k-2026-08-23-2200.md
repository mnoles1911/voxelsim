## UPDATE ~23:30Z — the 485,000/s reject ratio is EXPLAINED

The per-reason split (`Voxel admission detail`, `VoxelWorldSubsystem.cpp:11129`)
was added earlier tonight and **had never been read**. Aggregated over every
window of three matched legs already on disk:

    leg        rejBudget                rejCutoff        rejFine  rejNearest
    gp-ctl2    22,269,674  (99.13%)     195,889 (0.87%)  0        0
    gp-ctl     36,940,946  (99.47%)     198,005 (0.53%)  0        0
    pool-pri   36,314,438  (99.99%)       2,245 (0.01%)  0        0

**99.1-99.99% of all rejections are the per-call BUDGET gate** (`:14673`,
`AdmissionsThisLevel >= Cap/4`) — a pure counter test applied in ROW-MAJOR order.
Once a level hits its cap the sweep **stops admitting but does not stop
enumerating**: every remaining annulus cell still pays the Z-range memo, the Z
loop and two hash probes, then is thrown away. Level 0 alone is 71-83% of it.

**`rejFine = 0` in every window of every leg.** The fine-tile gate — the
constraint the entire streaming design is built around — rejects nothing.

An early `break` is NOT the fix: row-major order means the first `Cap/4` cells
are the scan box's CORNER, not the nearest chunks.

Falsified: the received "level 5's annulus rejected against an 84 m cutoff"
story. `rejCutoff` is level 0 only, first ~3 windows only, <= 0.87%.

### T4-2 mode 2 measured, and half of it is a REGRESSION
From `Saved/t42-live.log` flight windows (not the parked tail):
- **Exit walk: complete success.** `ms ev=0.02`/window, replacing an O(records)
  walk worth ~74 ms.
- **Entry walk: RELOCATED, NOT REMOVED.** `ms ad=636.87`/window — **2.4x worse
  than the 246-266 ms CPU recompute it replaces.** The GPU proposes 2.4M admits,
  the game thread evaluates every one, 95.4% die on the same budget gate.
  Nothing bounded the delta size. Aokana's "decouple, don't relocate" failure,
  and the `.usf` header warns about exactly this.

Fix authored: `-VoxelResidencyAdmitBudget=N` (default 0 = off, byte-identical),
branch `worktree-agent-residgpu-50k`, `3a6c44b`. The CPU's budget is a COUNT, so
the GPU emits the nearest that many: `EntryScanCS` runs twice, phase 0
histograms into 1024 equal-AREA bins over squared distance, `BudgetResolveCS`
prefix-sums per level and publishes a threshold, phase 1 emits inside it.
Projected 636.87 ms -> ~102 ms (B=256) -> ~26 ms (B=64); observed admissions are
264/delta so even B=64 has headroom. **The property that decides 50k is
flatness**: delta size becomes `sum_L B_L`, independent of span, where today it
is `|untracked ∩ annulus|` and grows as Span^2 — exactly as rings widen toward
the requested 8-10 km.

Mutation test required before believing any of it: `=1` must collapse `prop` and
starve; `=100000000` must give `budRej=0, admit==histTot` and match the `=0`
control.
