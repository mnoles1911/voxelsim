# Checkpoint storage: first implementation milestone

This implements the storage foundation of [the session persistence plan](session-persistence-plan-2026-09-07.md). It does not yet make all simulation domains persistent.

## Stored transaction

`VoxelCheckpointStore::Commit` writes terrain, detached objects and optional named-save metadata into a unique generation beneath `<logical-world-path>.checkpoints/`. The generation's versioned manifest lists payload filenames, sizes and MD5 integrity hashes. A separate `<sequence>-<guid>.commit` file contains the manifest hash. Publishing that record is the commit point. Readers choose the newest complete, supported committed generation; directories and `.tmp` markers alone do not count as saves.

This is an append-only commit index instead of a replaceable `current` pointer. A damaged newest generation can fall back to a complete older committed generation. An unknown manifest version fails closed. If committed records exist but none validate, the resolver refuses rather than opening the legacy file or an empty world. All required object data belongs to the same generation as terrain and metadata, even when terrain bytes did not change.

Writes use full file flushes. On Windows, the unique marker is published with `MoveFileExW(MOVEFILE_WRITE_THROUGH)` on the same volume. A named system mutex serializes commits to the same normalized logical path across processes. This is not a world-session ownership lock or a guarantee against external deletion. Real power-loss behavior and non-Windows directory durability still require platform testing.

## Integration

- `VoxelSaveJobs` uses the store on its worker after immutable object encoding.
- `VoxelSave::Write` captures and commits terrain, objects and metadata together. `ReadMeta` resolves metadata through the same generation as terrain.
- `SaveWorld`/`SaveWorldToPath`, including the current shutdown path, use the store. A world-only save inherits existing committed metadata; it does **not** refresh player position or play time. That remains a coordinated-capture task.
- `LoadEditLogFromPath` resolves before replay and starts object loading against the resolved path. Format/identity refusal protects both the logical destination and immutable payload; refused committed terrain is not moved or rewritten.
- Legacy files remain readable when no committed generation exists, and the first checkpoint leaves them untouched. There is no automatic worldgen/content migration.
- Detached/async offline verification scripts use `tools/checkpoint_store.py` to resolve new storage while retaining legacy fixture support.

## Tests

`Voxel.Persistence.CheckpointTransaction` exercises six interrupted pre-publication stages, identical-terrain/object-only saves, old metadata and legacy-byte preservation, missing required sidecar recovery, total committed-data loss refusal, metadata inheritance and malformed metadata rejection. Test artifacts live in unique `Saved/Tests/Checkpoints/<guid>/` directories and are retained for diagnosis.

Run through the worktree's built editor:

```text
UnrealEditor-Cmd.exe <project> -unattended -nop4 -nosplash -nullrhi
  -ExecCmds="Automation RunTests Voxel.Persistence.CheckpointTransaction"
  -TestExit="Automation Test Queue Empty"
```

Fault-stage interruption is deterministic failure injection, not a claim of physical power-loss testing. The existing `Voxel.Objects` tests provide companion coverage for object serialization and reconstruction.

## Remaining work and limits

### Simulation storage preparation

The opt-in version 2 storage API accepts immutable water, hydrology, and clock bytes together. All three nonempty payloads are mandatory, hashed, and flushed before publication. Resolution returns their paths from the same generation as terrain and objects. A caller omitting simulation data cannot overwrite a version 2 slot. Clock payloads are capped at 64 KiB; water and hydrology retain the 512 MiB payload cap. These are storage envelopes, not semantic validation of the domain codecs.

`Voxel.Persistence.CheckpointTransaction` now additionally tests all nine interrupted version 2 stages, removal of each required simulation file, recovery of the exact older domain bytes, refusal of empty domains, and refusal of a terrain-only downgrade. `tools/test_checkpoint_store.py` independently exercises complete and incomplete version 2 manifests, staging, corruption, and unsupported-version handling. Its validation remains enabled under Python `-O`.

Runtime capture and restore are now connected through `VoxelSessionCheckpoint`. Named sync saves, async saves, world saves, and the pre-teardown checkpoint include water, hydrology and clock bytes. The game thread captures water before terrain and objects; workers receive immutable bytes. SWE-owned volume is flushed into CA, and unconsumed spill transfers are returned to their scalar owner before serialization. The old independent water BeginPlay load and Deinitialize save calls have been removed. `SaveWaterState` routes through the coordinated world save.

Terrain replay precedes simulation restoration. Water and basin bytes are validated before applying either to a fresh water target. Water and sky ticks remain gated until restoration and asynchronous object loading succeed. Terrain load failures stop session startup; failed sessions cannot capture another save. The loading screen reports refusal and does not time out into gameplay. The final checkpoint runs in the existing object pre-teardown hook, after outstanding jobs are drained and while water/sky remain alive. The later terrain Deinitialize writer skips a final save already attempted.

Clock state includes the exact epoch, time rate, calendar dimensions and water fixed-step remainder. There is no wall-clock catch-up. Currently, rate/calendar and implicit-ocean configuration must match the saved values; mismatches refuse load rather than modify process-global cvars shared by multiple worlds.

Compatibility remains explicit: the default legacy slot can import its seed-based water/hydrology files. Legacy named saves have no trustworthy water association and initialize fresh water/time with a warning rather than import another branch's seed files. Fresh New Game never imports seed water. River-graph-bearing state is refused for both new captures and legacy imports because the old graph codec does not identify its generating region. Region identity, deferred routing restoration and river scheduling still need implementation; this is a restriction of this runtime milestone, not a completed river-persistence feature.
