# The 8 km cascade: adding R7, and what it dragged with it

**Owner asked for it on 2026-08-30** after the seam investigation, on the
understanding (stated before building) that **extending the cascade does NOT
narrow the seam** -- `AVoxelClipmapActor::SpacingUUForLevel` derives the
clipmap's vertex spacing as `ringEdge / HoleHalfIndex`, so doubling the cascade
doubles the clipmap's spacing too and the ~40:1 resolution ratio at the join is
preserved by construction. It was built for what it DOES buy: twice as much real
voxel terrain.

## What changed

The recipe was written down in `VoxelWorldSubsystem.h` by whoever removed the old
dormant R6, and it was correct as far as it went:

1. `VoxelCoords::kNumLevels` 7 -> 8
2. append `{4096.0, 8192.0}` to `kDefaultRingPresets`
3. `kRingCapShare` gains an eighth entry, 0.12 (levels 0-5 are the historic
   partition summing to 1.0; everything above is ADDITIVE, so appending does not
   re-tune the six below it)
4. `kDefaultMaxRingLevel` 6 -> 7

**Four more things the recipe does not mention**, each found by a static_assert:

5. `FVoxelMarchChunkIndex::kLevels` 7 -> 8, which carries `kRingGrids` and
   `kGridSlots` (= kRingGrids + 1) with it.
6. **The cover level had to move, 7 -> 8**, in BOTH of its spellings
   (`VoxelBrickPool.h`, `VoxelMarchChunkIndex.h`) -- R7 took slot 7.
7. **The VisBuffer level field, 3 bits -> 4.** Split rather than moved: the low
   three stay at `P.y[2:4]` and the fourth rides `P.y[30]`, which was free. This
   keeps Material, FaceNeighbourMask and the three LocalVoxel high-bit fields at
   the exact offsets every other consumer reads, so the widening cannot silently
   re-base any of them. (Five comments in the tree claimed 3 bits was a format
   ceiling. It never was.)
8. **Nine grid-slot arrays widened 8 -> 9.** The assert names two. The other
   seven are four more `MarchLevelChunkZ` parameter blocks, `MarchZTightSlabUU`,
   and `GVoxelMarchZCutRanZMin/Max` + `GVoxelMarchZTightRanZMin/Max` -- **the
   ZCut/ZTight pairs are not named by any assert and would have compiled clean
   while reading another slot's Z bound.**

**And one that fails SILENTLY, which is why the assert says "re-derived, not
patched":** `VoxelMarchHoleWord::UncReasonFirst = UncLevelFirst + 7` is a
hand-written literal. Get it wrong and the level words run one past their group
and overwrite the first reason word -- miss attribution reads garbage while every
counter stays healthy. It is now `+ 8` with a static_assert tying it to
`kNumLevels`, so it cannot drift again.

`VoxelResidencyScan.usf`'s `LevelRadiiA/B[8]` and friends are indexed per LEVEL,
not per grid slot: at 8 levels they are exactly full, and widening them would
have been a wrong guess dressed as thoroughness.

## The clipmap came along for the ride, and was cut back

The clipmap's outer half-extent is `16 x ringEdge`, so it went **65 km -> 131 km**
the moment the cascade doubled. Nothing is visible at 131 km -- this scene's fog
takes terrain to the sky's own colour tens of kilometres sooner (the far bands
measure (93, 109, 125), which is fog, not ground).

**Cut to 3 levels (was 4).** The extent is forced arithmetic -- the hole must
land on the cascade edge -- so the level COUNT is the only lever, and pulling it
is free: every level is a fixed 65x65 grid however far it reaches, so a wider
extent only spreads the same vertices thinner. Three levels give `8 x ringEdge`
= 65 km at the 8 km cascade, a finer outermost band for the same work, and a
quarter less per-rebuild vertex cost -- which now matters, because each vertex
costs a climate sample and a `vxc::classifyBiome` call on the GAME THREAD.

## The gate leak: TWO leaks, opposite answers, and a stack trace that ended it

**Leak 1 -- a real bug this change introduced, now fixed.**
`FMath::Clamp(CoarseLevel, 0, 6)` in `VoxelGpuRegionBuild.h`'s
`ComputeRasterWindowPx`, and its twin in `VoxelGpuWorldGen.cpp`'s
`FillLooseParameters`. R7 shipped with both still at 6, so every level-7 chunk
sized its raster window against a HALF-SCALE cell-to-world mapping. The symptom
was not a small window: it was a fine-tier gate leak with an elevation query
**42.8 km from the player**, through `FVoxelRasterAtlasCpu::FillWindowOnDemand`.

**No static_assert could catch it.** `VoxelEarthShaders` may not depend on
`VoxelEarth`, so it cannot read `VoxelCoords::kNumLevels`; the two spellings are
kept in step by a COMMENT. That comment had even pre-named the failure shape --
"the D5 failure again, one level up" -- and this change reproduced it one level
further up still. **A constant that cannot be asserted across a module boundary
is a constant that will drift.** The lasting fix is exporting the level count
where both modules can see it; that is NOT done.

**What actually found it:** a symbolicated stack dump added to
`ReportGateLeak_Locked`, on the FIRST leak only (this class of bug once fired
18.7 million times, so a walk per leak becomes the thing being diagnosed). Three
builds went on eliminating the clipmap and the atlas sweep by measurement, one
candidate each. The stack named the caller in one leg. **Add the instrument
first next time.**

**Leak 2 -- a genuine coverage gap, and the opposite conclusion.** With leak 1
fixed, a second leak appeared from `FVoxelRasterAtlasCpu::Tick` at tile (-4,-6),
**9.3 km from the camera** and inside the atlas's own 8.19 km coverage. The 8 km
cascade reaches ground the 4 km cascade never asked for, and the baked set around
tile (-4,-5) was missing the entire -6 row.

**CHECK THE DISTANCE BEFORE BAKING.** The gate prints it and says so itself:
past a couple of tiles it "is too far to be a coverage gap ... no ring radius or
bake would prevent it." At 42.8 km baking would have burned ~35 minutes and left
the bug in place. At 9.3 km baking is exactly right:

    python -m terrain_service.pregen --seed 20260719 --mode bake         --center-x -4 --center-y -5 --radius 1 --cache-dir D:oxelsim	ile-cache

(tile coordinates, generates the (2r+1)^2 square, skips what is already cached.)

## Still open

`-VoxelFineTileDir=` as a bare switch does NOT force the coarse tier from a leg
command line: `FParse::Value` swallows the following token, so the fine tier ends
up rooted at whatever argument came next (observed twice: `-VoxelMaxRingLevel=6`
and `-game`).
