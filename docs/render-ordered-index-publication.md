# Render-ordered terrain index publication

Status: audited prerequisite, not implemented. Keep production terrain-to-object publication disabled until this seam and frame capture acceptance pass.

UE5.8 guarantees proxy updates before a new view family: Actor.cpp SetActorHiddenInGame calls UpdateComponentVisibility; registered components mark render state dirty. SceneRendering.cpp BeginRenderingViewFamilies calls World->SendAllEndOfFrameUpdates (around5380), then RenderCommandPipe::FSyncScope (around5411), before assembling deferred captures/linked renderers and executing rendering. A non-yielding game-thread batch followed by actor reveal can therefore use this existing boundary for the subsequent family. A custom actor proxy is not currently justified.

The current default march index breaks the remaining ordering proof. Pool Flush enqueues its upload and invokes IndexSink synchronously. ApplyDelta -> MarkDirtyAndUpload assigns shared Staged/bStagedValid on the game thread. An older already-queued view can reach Register and consume that future staging before the newly queued pool upload and actor visibility commands execute. Coarse block generations/mirrors have the same exposure. A lock prevents a data race but does not fix this temporal race.

Use one render-thread-owned canonical index image and immutable update packets installed by an ordered render command behind the corresponding pool writes. Include cells, coarse occupied/absent/all-sky mirrors, epoch/generation and verification policy together. Register must consume only installed render-thread state, never the latest mutable game-thread staging. The optional GPU-resident path and fallback must preserve the same ordering.

Current dimensions are nine128-cube slots:72MiB for full index cells and108KiB for the three coarse mirrors. Ordinary packets should contain unique changed cell index/value pairs plus coherent coarse mirrors; seed/reset can carry a full image. Track changes independently from the existing full-versus-delta GPU upload option. The default GPU full upload need not change when correcting CPU thread ownership. Coalesce only after ordered installation on the render thread, preserving command positions; an earlier command must never consume a later mutable mailbox.

Queue-memory admission must precede corresponding pool publication. IndexSink currently returns void, so silently dropping or deferring an update after replacing pool pages is unsafe. The pilot needs a reserved packet/queue budget during prepared-batch preflight. Ordinary streaming needs equivalent producer admission or a bounded immutable snapshot design. Epoch retirement and resource release must also be ordered; queued commands should own shared lifetime state rather than borrow a destroyed index.

Regression sequence: installA; queue an old view; constructB onGT before allowing that old view to execute; enqueue/installB; queue a new view. Old view must still seeA cells/coarsebits/generation, new view must seeB. Cover mergedC/D patches, full/patch transitions, reset epochs, rejected generation gaps, destruction with queued commands, and failed/abandoned GPU extraction retry. Then capture actual main view/depth/shadows/captures across pool+actor commit. Dispatch before the first relevant family if the guarantee must span an entire display frame; cached/time-sliced reflections retain historical frames independently of transaction correctness.
