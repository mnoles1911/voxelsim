TWO BUGS THIS GATE FOUND ON ITS FIRST RUNS, both in the harness/plumbing rather
than in the kernel, and both silent:

1. RASTER WINDOW SIZED IN LEVEL-0 VOXELS. At level L a dispatch samples over a
   span 2^L wider than its column count, so the window was far too narrow and
   the kernel CLAMPED reads to its edge -- exactly the failure
   VoxelGpuRegionBuild.h's own header warns about, and it does not fault, it
   just silently produces different terrain.
     signature: [origin] passed columns AND cells at L1 (small coordinates, the
     margin still covered it) while [far-negative] reported 12,288 column and
     108,470 cell mismatches. A bug in coarseRep itself would have failed both.

2. Req.CoarseLevel WAS SET AFTER FillRasterWindow READ IT. The fix above was a
   no-op for one whole run and the numbers did not move at all -- which looked
   like the hypothesis being wrong rather than the fix not having been applied.
   Same ordering class as SetChunkTableCapacity-after-RegisterComponent.

3. CPU QUAD REFERENCE SAMPLED AT LEVEL-0 z. Once columns and cells were exact,
   the quad comparison read "cpu=0 gpu=3354", which at a glance reads as the GPU
   inventing geometry. It was the reference not being asked for any: at coarse z
   every sample came back solid, no face had an air neighbour, so meshBrick
   emitted nothing.
