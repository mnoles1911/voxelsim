# Front-end switch classification -- the input to
# tools/lint-frontend-switch-coverage.py.
#
# WHAT THIS FILE IS FOR
# ---------------------
# VoxelFrontEndPolicy decides, per run, whether the main menu appears. Its
# rule 5 suppresses the menu whenever a "self-driving" switch is on the command
# line -- one whose run spawns, poses, waits and captures with no human
# present. Such a run must never stop at a menu nobody is there to click.
#
# That classification is a NAMING-CONVENTION RULE in VoxelFrontEndPolicy.cpp
# (a switch containing Test / Shot / After / Check / Verify / ... drives
# itself), not a list, because a list of ~190 names is wrong the first week
# somebody adds -VoxelFooTest and forgets to update it.
#
# The rule cannot classify everything, though, and the failure is silent: a new
# -VoxelSomethingFixture would fall through as "tuning", the menu would appear,
# and the capture would hang until the watchdog killed it. This file is what
# makes that failure LOUD instead. Every switch the rule does not match must
# appear below, confirming a human decided it is ordinary tuning or
# configuration. The lint fails on anything unlisted.
#
# TO ADD A SWITCH
# ---------------
#   * Does the run drive itself and quit?      Name it *Test / *Shot / *After,
#                                              and the rule handles it.
#   * Is it configuration or tuning?           Add its name here.
#   * Neither of those fits?                   Add it to kSelfDrivingExtras in
#                                              VoxelFrontEndPolicy.cpp, with a
#                                              reason.
#
# Blank lines and #-comments are ignored. One switch name per line, without the
# leading dash and without a trailing '='.

# --- 2026-08-23: far-clipmap appearance (docs/backlog.md 0.0d) ---------------
# All tuning, diagnosis or configuration; none of them drives the run, so all of
# them belong here rather than in kSelfDrivingExtras.
#
# VoxelClimateSentinelGuard=0 turns OFF the floor that stops terrain writing the
# byte pattern M_VoxelTerrain/M_VoxelClipmap reserve for a debug marker. It is
# the A/B arm for the magenta fix, not a feature switch -- passed, cold-and-dry
# ground draws bright magenta again on purpose. See VoxelClimateProbe.h's
# kSentinelSafeFloorU8 for the measurement.
#
# The four VoxelClipmapSnow*/Snowline* switches move M_VoxelClipmap's snow
# parameters at runtime through a per-level MID. With none of them passed no MID
# is created and the frame is byte-identical to one taken before the change,
# which is why they are tuning rather than a mode.
#
# VoxelClipmapColorCensus only adds log lines. It is deliberately NOT named
# *Check or *Verify: those endings make VoxelFrontEndPolicy treat the whole run
# as self-driving and suppress the menu, and this switch is meant to be readable
# on an ordinary interactive flight where the owner is the one looking at the
# vista.
VoxelClimateSentinelGuard
VoxelClipmapSnowlineLowM
VoxelClipmapSnowlineHighM
VoxelClipmapSnowTempMax
VoxelClipmapSnowTempFeather
VoxelClipmapColorCensus

# --- 2026-08-23: the fine-tier sampler lock ---------------------------------
# ue-project/Source/VoxelEarth/VoxelFineLockMeter.h and VoxelFineTileStreamer.
# Both are tuning/instrument: -VoxelFineLockFast picks how RequestFootprint
# acquires the streamer's RWLock (0 = today's unconditional exclusive), and
# -VoxelFineLockMeter arms the acquisition counters. Neither drives, poses or
# ends a run, and both are meant to be readable on an ordinary interactive
# launch.
#
# THE METER IS NOT CALLED *Probe ON PURPOSE, and the near-miss is worth
# recording: "Probe" is in kSelfDrivingSubstrings, so -VoxelFineLockProbe would
# have matched the rule, suppressed the main menu, and never appeared in this
# file at all -- a passive counter quietly taking the front end away from a
# developer who only wanted the numbers. Renamed rather than excepted, because
# the rule is right and the name was wrong.
VoxelFineLockFast
VoxelFineLockMeter
